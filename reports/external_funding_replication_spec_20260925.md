# External-exchange replication specification checklist

This is a **second-stage, Binance-motivated replication** of the already frozen funding claim, not a fresh first hypothesis. It authorizes no return calculation or alpha search. Before any external-venue strategy return is calculated, complete a new preregistration and pin a `research.data_snapshot` manifest hash for `external_replication_v1` (or a clearly named successor). A later data correction requires a new version; never overwrite the original.

## Freeze the data-generating environment

- [ ] Name one primary legally accessible venue, market segment, API/archive version, retrieval time, and exact endpoint/URL for every file. Commit the full archived historical universe, including inactive and delisted contracts, and an independent source of listing/delisting dates where possible.
- [ ] Freeze contract identifiers and point-in-time mappings: linear/inverse format, quote/margin asset, contract multiplier, redenominations, token migrations, symbols reused by the venue, index/non-crypto exclusions, and stablecoin conversion rules. Do not use today's live-contract list as the historical universe.
- [ ] Freeze raw funding records with **exact event timestamp, publication/availability timestamp, rate, interval, and settlement currency**. Specify whether 00:00 funding is earned by the pre-open or post-open holder. Prohibit use of a settlement first known after portfolio formation in the signal.
- [ ] Freeze futures (not spot) open/close or executable quote timestamps, the exchange timezone, clock convention, missing intervals, daily bar construction, and quote-volume units. Spot can be retained for diagnostics but must not silently replace futures execution prices.
- [ ] Freeze every input and generated artifact, including complete per-day eligibility/universe membership, exclusions, symbol mappings, fee schedule, delisting table, intermediate bars and funding aggregates. Record SHA-256, byte size, provenance, retrieval time, logical as-of, instrument, first/last timestamp and row count. Register the deterministic manifest hash and make the evaluation command verify it before running.

## Preserve the economic rule, with venue mechanics stated in advance

- [ ] Commit the frozen economic orientation: **long lowest trailing funding, short highest**. No reverse sign, alternate signal, subset, leverage or optimized variant.
- [ ] Commit the closest implementable equivalents of the Binance rule before examining returns: 60 prior kline days and preceding-day bar; top 100 eligible USDT-equivalent linear perps by median prior-30-day quote volume (with an explicit minimum-observation rule); sum of settlements in `[t-7 days,t)` divided by seven and at least ten settlements; bottom/top `floor(0.2 × universe size)` with lexical or otherwise fixed tie-break; +0.5/−0.5 equal-leg gross, minimum 25 eligible names. Any unavoidable venue-specific deviation must be named and justified as a separate comparability limitation before returns.
- [ ] Specify opening/rebalance time, order type, execution delay, spread/slippage, maker/taker selection, fees, minimum lot/notional, margin/borrow constraints, and the rule for weight drift between rebalances. Simulate funding cash transfers at actual event timestamps and the contract notional held at those times.
- [ ] Specify a point-in-time delisting exit rule using executable last trade/mark/settlement information, and a separate missing-data rule. Do not label temporary kline gaps as delistings. Freeze base and stress exit assumptions and any exclusion for unpriceable contracts.
- [ ] Freeze daily NAV accounting, gross/net exposure checks, price P&L, funding cashflows, fees, FX/stablecoin conversion and margin/funding treatment. Reconcile components and include delisted instruments in the reconciliation.

## Freeze inference and interpretation

- [ ] Designate **one primary external sample and venue before returns**. Record every venue tried, including failures. Because this test was motivated by Binance, describe it as conditional second-stage replication; do not claim a new first-hypothesis p-value. Precommit the one-sided null, an explicit significance threshold (recommended no looser than **0.025** for one primary attempt), and a multiplicity correction if more than one venue/window is attempted.
- [ ] Precommit the block-bootstrap algorithm, centering convention, seed/draw count, **primary block length**, and sensitivity lengths. Preserve all contracts' returns and market shocks together by resampling dates, not individual contracts. Define a nonstationarity check across calendar regimes, universe sizes and delisting episodes. Do not select the block length after viewing p-values.
- [ ] Precommit factor diagnostics: BTC, ETH, the true equal-weight eligible-universe return, quote-liquidity/size proxies, prior volatility, prior momentum, dollar and beta neutrality, asset/month/year contribution, and funding-versus-price-versus-fee decomposition. These are explanatory outputs, not controls used to improve or residualize the strategy.
- [ ] Precommit the **effective-sample-size estimator** (e.g. autocorrelation/HAC-based) and minimum acceptable effective size before returns. The realized effective sample size itself cannot be frozen before observing returns; report it afterward with the planned estimator and block-count diagnostics. State that the effective number of independent regimes may be far smaller than the number of daily bars.
- [ ] Record the original Binance development failure and archive-version weakness in the eventual external report. A favorable venue result would support transportability only to the extent that data coverage, venue mechanics and second-stage selection have been handled; it would not alter the old PASS/FAIL verdict.
