# Data snapshots for future preregistered experiments

Use `python -m research.data_snapshot` before calculating the first strategy return. This is a new-workflow requirement; it does **not** reopen or change prior verdicts or the frozen Binance implementation.

1. Finish acquisition, point-in-time symbol mapping, delisting reconciliation, and every generated input (bars, event aggregates, dynamic universe membership, exclusions, mappings, intermediate feature tables) **before returns**. Put all files the evaluation can consume under explicit watched scopes. A scope's `include` patterns are fixed in the manifest, so a newly downloaded matching historical file makes a live run fail.
2. Provide a JSON spec with `dataset_version`, `scopes`, `metadata`, `universe` and `intermediate_artifacts`. Metadata is keyed by `scope_name/relative/path` and must contain source, source identifier/URL (nullable when unavailable), ingestion-record retrieval timestamp, logical as-of date, instrument, first and last data timestamps, and row count. Static artifacts may have null timestamps only with `temporal: false`. Do **not** substitute filesystem mtime for retrieval time. The complete daily membership is a required frozen artifact, not merely a list of today's symbols. Universe exclusions, symbol mappings and delisting information are stored in the manifest, with any larger companion tables named as frozen artifacts.
3. Run `python -m research.data_snapshot --store /absolute/snapshot-store freeze /absolute/spec.json`. Record the printed manifest SHA-256 in the experiment's preregistration alongside its code hash, hypotheses, gates and inference choices. The payload is canonical JSON; repeated freezes of identical paths, bytes and metadata have the same hash. A dataset-version name is immutable. Use names such as `dev_snapshot_v1`, `external_replication_v1`, or `forward_snapshot_YYYYMMDD`; corrected data require a new version.
4. Register a command JSON array with `python -m research.data_snapshot --store /absolute/snapshot-store register EXPERIMENT VERSION /absolute/command.json`. The command must include both `{snapshot_root}` and `{membership_path}` placeholders and must read **only** from that frozen view. For a live-source run, execute `python -m research.data_snapshot --store /absolute/snapshot-store run EXPERIMENT`. It verifies the registration, manifest hash, all frozen content objects, all watched live source files, absence of new files, and membership artifact **before** launching the command. Failure is fatal; do not fall back to the mutable archive.
5. To reproduce an old snapshot after the public source changes, use the explicit `run EXPERIMENT --replay` form. This verifies the same registered hash and content-addressed objects, but deliberately ignores live-source drift because the command reads only the immutable snapshot view. Label this as a replay. It is not permission to mix a new file into the old version.

The store keeps one checked content-addressed object per unique SHA-256 across versions and a symlink view for each version. It attempts filesystem copy-on-write cloning on APFS/Linux reflink, then streams a copy if cloning is unsupported. **It never hard-links to a mutable input inode**, which would not survive an in-place vendor correction. Data bytes are hashed again after copying. Backup the snapshot store and pin the manifest hash in version control or an independent append-only registration record; a lost object cannot be reconstructed from a disappeared vendor file. Verification is intentionally I/O-intensive for large datasets, but file bodies are hashed in bounded memory and never loaded all at once.

The snapshot system verifies bytes and metadata *identity*, not the truth of user-supplied provenance or the completeness of an acquisition. The ingest step must validate row counts, time bounds, URL/identifier, symbol identity, and delisting records before freezing. The evaluator must not reach around the `{snapshot_root}` path to a mutable archive. These are pre-return review checks, not properties a hash can infer.
